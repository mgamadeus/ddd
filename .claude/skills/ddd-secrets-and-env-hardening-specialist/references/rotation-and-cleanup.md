# Rotation and post-cleanup checklist

Contents: 1 Order · 2 Internal keys · 3 External keys · 4 Infrastructure credentials · 5 Cleanup · 6 Gate before deploy

## 1 Order — additive first, destructive last

**new → deploy → verify → then delete old.** Every external provider that allows several active keys
gets a new key while the old one keeps working; the old one is revoked only after the app runs on
the new one. Exceptions that are NOT additive (regenerating invalidates the old one immediately —
do it in the same change as the deploy): Strava client secret, most OAuth client secrets.

The working file is the plaintext copy (`.env_backup`, gitignored): externals pasted in by hand,
internals regenerated by `rotate_env_secrets.py --file .env_backup`, then ALWAYS
`op_import_env_secrets.py --env .env_backup …` — **the item is a copy of the file, never the other
way round.** Both scripts refuse to run without an explicit `--file`/`--env`: their tempting default
would be the placeholder `.env`.

## 2 Internal (script-generated) keys — mgamadeus/ddd apps

| Key | Rotate? | Effect |
|---|---|---|
| `APP_SECRET`, `ENCRYPTION_COOKIE_PASSWORD` | yes | sessions/cookies invalid → everyone logged out once |
| `JWT_HASH_KEY` = `AUTH_JWT_HASH_KEY` | yes, **as a pair** | all JWTs invalid → everyone logged out once |
| `AUTH_PASSWORD_HASH_KEY` | only if passwords are `password_hash` (Argon2id/bcrypt) | if the app does `hash_hmac(method, plaintext, AUTH_PASSWORD_HASH_KEY)` the key is a live pepper: rotating it invalidates every password — reset them (`app:accounts:set-password`) or keep the key |
| `PASSWORD_HASH` | only if no entity column uses `enryptionScope` (sic) | it salts the `Encrypt` helper for DB column encryption |

Check before rotating: `grep -rn "hash_hmac\|password_verify\|enryptionScope" src vendor/mgamadeus/ddd/src`.
A docblock mentioning "legacy HMAC rehash" is not proof — read the code path.

## 3 External keys

Google Maps/Places: create a NEW key restricted to the APIs actually used (`gcloud services api-keys create --api-target=service=…`),
never edit the leaked one in place. Check billing/API metrics for the leak window on the old key.
Service-account JSON (Firebase, Workspace): `gcloud iam service-accounts keys create` → base64 into the
file → later `keys delete <old id>`. OpenRouter/OpenAI: new key, then delete ALL old keys and check the
usage log for foreign source IPs. Confluence/Jira tokens: new token, revoke old, note the expiry.

## 4 Infrastructure credentials

DB: create a NEW user with the new password, deploy, drop the old user (Galera replicates the DROP).
DB usernames are secrets too (half of the credential pair) — `op://` reference, checker rule `^DB_.*_USER$`.
Redis `requirepass`/Sentinel auth: change in one go with the deploy. RabbitMQ DSN: new user, and
**restart the workers** — a compiled container keeps the old DSN (`--no-debug` stale-container trap).

## 5 Cleanup (only after verification)

- Old DB users dropped; old API keys / SA keys / tokens deleted; old key → 401 verified.
- Plaintext copies destroyed: `.env_backup*`, `.env.bak*` on the laptop AND in rsync'd dev workspaces;
  IDE deployment "excluded paths" updated so they never sync again.
- `var/cache/*/profiler` deleted everywhere (stored requests contain the OLD env).
- CI parameters holding the old plaintext `.env` removed (obsolete once op run delivers).
- Every field of the item carries a value created AFTER the incident window.

## 6 Gate before the deploy

- Connect server created with READ on exactly the app's vault; token stored as a compose secret file.
- Compose: `OP_VAULT`, `OP_ENV_FILE`, `OP_CONNECT_HOST`, `OP_CONFIG_DIR`, `BASH_ENV`, `APP_ENV=prod`, `APP_DEBUG=0`.
- `op item get <item> --vault <vault>`: no empty field, `updated_at` after the last change.
- `.env` committed secret-free (checker passes), `.env.local` absent from the prod checkout.
- Container `php -i | grep variables_order` contains `E`.
- Deploy step, cron line and supervisor start use `BASH_ENV` (never `service supervisor start`).
